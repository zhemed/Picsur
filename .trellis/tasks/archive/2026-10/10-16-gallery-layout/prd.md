# 图库页布局与清晰度重做

## 现象（用户截图）

- 每张图**高度不齐** → 栅格像"瀑布流没对齐"，视觉很乱 ✗
- 标题**截断不一致**、上传时间行排版松散 ✗
- **图片不清楚** → 疑似把缩略图**拉伸/放大**填满卡片（而非按原生比例缩放）✗
- **手机端**体验差（列数、触控目标、按钮命中）✗

## 要求

1. **统一比例**：卡片缩略区用固定宽高比（如 4:3 或 1:1）+ `object-fit: cover`，栅格严格对齐；标题单行省略（`text-overflow: ellipsis` 统一）、时间行统一高度；
2. **清晰度**：按**实际显示像素**请求派生图（带 `width/height` 参数或 `srcset`），**禁止放大**（显示尺寸 ≤ 原图/派生图尺寸）；高分屏（DPR=2）要取 2×；确认服务端派生图链路给的尺寸与前端请求一致；
3. **响应式**：桌面 3~4 列 / 平板 2~3 列 / 手机 1~2 列（断点明确写死），触控目标 ≥44px，按钮在窄屏可点且不重叠；
4. **移动端**：验证横向不溢出（无横向滚动条）、标题与按钮不挤压；
5. 不改变上传/删除/查看的**功能语义**（纯展示层）。

## 验收

- [ ] AC1 **先量**：改前在 3 个宽度（如 1440 / 834 / 390）各截一张 + 记录卡片 rect 与图片自然尺寸/显示尺寸比；
- [ ] AC2 改后同口径复验：三宽度截图；断言**同一行卡片高度一致**、**无放大**（显示尺寸 ≤ 源尺寸）、**无横向滚动**；
- [ ] AC3 对比度探针 26 页 PASS 不回归；三包构建；
- [ ] AC4 桌面/手机各一张"看得清、排得齐"的成品图。

## 追加项（用户 2026-10-16 拍板：做）

**图片列表接口补原图宽高** → 前端首次即可算出准确请求尺寸，省掉"先猜再纠正"的第二次图片请求（省流量、首屏更快）。

- 后端：列表/条目响应里补 `width` / `height`（原图尺寸；**不要求解码**，入库时或首次访问时记录即可，注意老数据与未探测过的图片要能优雅降级为 `null`）；`shared` 的 DTO/类型同步。
- 前端：`picsur-img` 在有宽高时**直接**按 `绘制尺寸 × DPR` 请求（不再二次纠正）；缺失时行为回退到现在的"先猜再纠正"，不得回归。
- 验收：① 新上传的图首次加载只发**一次**图片请求（用探针或网络日志证明）；② 老图（无宽高）仍走回退路径且**无放大**；③ `support/gallery-layout-probe.cjs` 六组全 ok；④ 34 项回归 + 对比度探针 28 页。
