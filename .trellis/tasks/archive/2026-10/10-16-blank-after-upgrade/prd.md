# 升级后页面内容一闪就没（空白）

## 现象

用户截图：页头（logo + 三个图标）在，**内容区全空** ✗；描述"好像已经加载出来了，但有问题一闪就没了，然后一直这样" → 典型**渲染后被异常打断**（Angular 清空路由内容）或**反复 reload** ✗。

## 要求

1. 用常驻浏览器（`bw`）直接打开该实例，抓**真实控制台错误**与 DOM（router-outlet 是否有内容、是否在反复导航/reload）；
2. 定位到具体文件:行；判断与 0.10.3（图库原生 `<img>` + WebP）或升级后的 reload 逻辑是否相关；
3. 给出修复（若后端/前端分工，交对应线，Lead 复核）；
4. 验收：页面正常渲染、无异常、刷新/导航均不再空白。

## 验收

- [ ] AC1 抓到真实错误信息（非推测）；
- [ ] AC2 根因 file:line；
- [ ] AC3 修复后同场景复测通过（含连续点击与刷新）；
- [ ] AC4 版本发布并在用户实例验证。

## 结案（用户确认）

> 这次好了，几乎秒出图

**真因**（由用户两次质疑逼出的实测结论）：**不是**响应校验 ✗（用户库里没有 ≤0 的行 ✓，NULL 实测 201 ✓）；而是**前端在列表请求失败/挂起时无超时、无错误处理** ✗ → 永远停在「加载中」✓。修法：10s 超时 + 可读错误 + 重试 ✓、缩略图不参与页面 loading ✓。

**同时修掉的真实隐患**（非本机原因但确实存在）：`width/height = 0` 会让 `/api/image/list` **整个 500** ✗（本地逐值 A/B 证明：NULL→201 ✓、0/负数→500 ✗）→ schema 放宽为 `nonnegative().nullable()` ✓，并新增**老行回归**（旧代码 37/1 红 → 新代码 38/0 绿 ✓）。

**发布**：0.10.4 ✓；用户实例复测：图库正常、几乎秒出 ✓。
