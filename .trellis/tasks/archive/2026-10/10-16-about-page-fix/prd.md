# 网页端一键升级（主线目标）—— 状态机 + 进度 + 成功自动刷新

## 现象

管理员打开「关于与升级」：`最新版本` 显示「未知」、提示停在「正在检查更新…」、并显示「面板内升级未启用」
与手动升级命令；但后端 `POST /api/system/update/check` 实测返回 `current=0.8.0 latest=0.8.0 updateAvailable=false selfUpdateEnabled=true`。
页面底部显示 `V0.8.0`（bundle 是新的，排除缓存）。

## 判定

前端检测更新链路（`api.service.ts` 的响应解析 + `info.service.ts` 语义）在 0.8.0 合并后出现回归：
请求未成功落到 UI 状态，既没有 `latest` 也没有 `selfUpdateEnabled`，于是显示兜底文案且 loading 永不清除。

## 验收

- [ ] AC1 管理员的「关于」页在**后端正常**时显示 当前/最新版本 与「已是最新版本」或可用按钮，且 loading 会结束。
- [ ] AC2 **后端异常/超时**时不再假称"未启用"或永久"正在检查"，给出可读原因与「检查更新」重试。

## 主线目标（用户 2026-10-16 重申，最高优先级）

> 我要的目标一直都是网页端直接更新

**"网页端直接更新"的验收标准（发布 0.8.1 必须全部满足）**：
1. 点「检查更新」：正常时秒级给出 当前/最新；冷缓存（服务端要问 GitHub）时**最长 15 秒**给出结果或明确失败提示；
2. 点「立即升级」：**显示"正在升级…"与当前阶段**（拉镜像 / 重建 / 起新版），不是静默；
3. 升级成功：**页面自动变成新版**（自动刷新或热切换），不需要用户强刷/SSH；
4. 升级失败：显示**"已回滚到 X 版本"**与原因，并提供重试；
5. 全程不需要 SSH、不需要手动 `docker pull`。

**已完成**：状态机与 15s 超时（`fc44de0`，分支 `fix/about-state-machine-2`）——解决"永久正在检查 + 未知被显示成未启用"。
**待做**：进度显示 + 成功自动刷新 + 失败回滚提示与重试（前端即可，`check` 返回的 `lastUpdate.state/message` 足够驱动）。
