## 用户决定（2026-10-16）

- **API 密钥**：直接移除 ✓（后端 `fix/slim-apikeys` @ 0f254fd 已完成，前端 `zh-default` 同版删）。
- **用户与角色**：选 **③ 彻底去角色化** ✓ —— 取消"角色"概念，改成**在用户页直接勾权限**（代价 3~5 天：新列 + 迁移 + admin 特例 + demo 模式改写）。
- **系统设置**：调查结论为 **12 项 → 保留 5 / 固定默认撤 UI 5 / 删除 2**（`EnableTracking` 是死设置、`EnableTelemetry` 无端点、`JwtSecret`/`JwtExpiresIn` 只在启动读却冒充实时并可明文回显、`BCryptStrength` 无上限会自锁）—— 待用户拍板。

## ③ 的实施约束（来自调查）

- demo 模式依赖"运行时改 guest 角色权限"（`demo.service.ts:20`）→ 去角色化后必须给出替代方案；
- admin 用户改角色目前**静默失败**（`user-db.service.ts:98-102`）→ 改造时一并修或在用户页对 admin 只读；
- `RolePermissionsLocks` 只剩一条约束 → 一并清理；
- **不做破坏性迁移**（角色表可保留不删）；升级到旧库时 `user` 角色里那条死字符串 `apikey` 属外观问题（不授权任何能力），可单独一条 6 行 migration 清掉。
