# 全项目隐藏问题扫描

## 目标

用团队对整仓库做一次**只读审计**，找出"隐藏问题"——不是已知待办（Angular 升级、存储后端），
而是我们没意识到或没验证过的：安全、正确性、契约漂移、运维与供应链、文档与实现不一致。

## 三条战线（互不重叠）

| 线 | 范围 | 重点 |
|---|---|---|
| A 后端/共享 | `backend/**`、`shared/**` | 授权与权限判定（越权）、输入校验（zod DTO vs 实际路径）、SQL/查询安全、文件与上传处理、sharp worker 协议与资源上限、迁移安全与可重入、错误码语义、日志泄密 |
| B 前端 | `frontend/**` | XSS/注入（`innerHTML`、URL 拼接、SVG/CSP）、客户端权限假设与后端是否一致、i18n（裸 key/漏翻/词典漂移）、与 `shared` DTO 的契约漂移、缓存与服务工作者、浏览器侧依赖告警 |
| C 运维/供应链/仓库 | `Dockerfile*`、`docker-compose.yml`、`install.sh`、`support/**`、`.github/**`、根配置、`.trellis/**` vs README | 依赖审计（prod + 全量）、镜像与构建可复现性、脚本健壮性（参数/幂等/失败路径）、CI 与发布口径、仓库与历史里的密钥/主机信息、许可与出处合规、文档与实现是否一致 |

## 交付要求（三线一致）

每条发现给：**严重度**（阻断/高/中/低）、**证据**（`file:line` + 具体代码或命令输出）、
**为什么是真问题**（不是"看起来不优雅"）、**建议修法**、**验证方法**（怎么证明修好了）。
并明确列出"扫了哪些范围 / 哪些没扫 / 哪些拿不准"，避免虚假覆盖。

## 约束

- **只读**：不改仓库、不提交、不推送；不在常驻实例（8080）上做破坏性操作。
- 不引入网络动作（除已有的 registry 审计）；不碰用户的其它服务。
- 结论必须可复现：给出命令，Lead 会抽样复核。

## 验收标准

- [ ] AC1 三线各自提交发现清单（含严重度/证据/验证方法/未覆盖范围）。
- [ ] AC2 Lead 对每线的**至少一条**发现做独立复现（抽掉误报）。
- [ ] AC3 汇总成一张按严重度排序的表，附"真问题/误报/需用户决定"三类标注。
- [ ] AC4 由用户决定修哪些；未修的进任务记录备查。
