# 接续被中断的收尾

## 背景

- 上一轮"合并 `fix/ci-spec-globals-rule`（spec 制度一条）+ 推送"的工具调用**被中断、结果未知** ✗ —— 可能已合并已推送，也可能完全没执行。
- 用户连续两次遇到中断，要求：`进行到哪里了，继续`。

## 要求

1. **先核实外部状态、不盲重试** ✗（合并/推送是有副作用的操作）：确认本地/远端 master sha、未推送提交数、`fix/ci-spec-globals-rule` 是否已合并、CI 最近结论；
2. 按核实结果**补完**剩余动作（若未合并则合并并推送 ✓；若已合并则跳过 ✓）；
3. 收干净尾巴：已合并的分支/ worktree 清掉 ✓、完成的任务归档 ✓、journal 留痕 ✓；
4. 向用户汇报"续到哪里了 + 当前基线（master / CI / 线上版本）"。

## 验收

- [ ] AC1 本地与远端 master 一致、工作区干净；
- [ ] AC2 该合并的提交确已在 master 上（用 `git log`/`git branch --merged` 证明 ✓，不靠猜 ✓）；
- [ ] AC3 CI 最近一次结论为 success（或说明为何仍红并给出下一步 ✓）；
- [ ] AC4 残留（worktree/分支/已完成任务）清理完毕；
- [ ] AC5 汇报里给出可核对的 sha 与链接 ✓。
