# 精简一轮

## ① 移除 API 密钥（直接做）

范围：前端设置页入口/页面/路由/词典 + 后端端点、鉴权策略与相关服务。
**不做破坏性迁移**（不 drop 表、不删用户数据）—— 表保留但不再被使用，在报告里说明"以后可单独清"。
**要提示用户**：任何用 API 密钥上传的第三方工具会随之失效（ShareX 已移除 ✓）。

## ② 调查：用户与角色能否合并（只出方案）

现状：用户可挂多个角色，角色持有权限清单，可自建角色。
要回答：合并成什么形态（例如"只有内置 admin/user/guest + 在用户页直接勾权限"？）、会失去什么（自定义角色）、改造量、对现有数据/权限判定的影响、推荐与否。

## ③ 调查：系统设置能否精简（只出方案）

现状：`/settings/system` 里一堆偏好。要逐项列出：**这一项实际控制什么、默认值、是否真的需要暴露给用户、能否删掉/固定为默认**；给出"建议保留 / 建议固定默认不再暴露 / 建议删除"三档清单与理由。
